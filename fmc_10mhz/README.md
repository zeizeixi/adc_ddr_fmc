# FMC 10 MHz 升级：保留 L21 接线

适用于之前的 `fmc_integration` 接入包，FPGA UI 时钟保持100 MHz。原5 MHz目录和用户工程均保留。

## 加入当前工程

1. 备份工程后，用 `rtl/fmc_sdram_port.v` 替换原同名模块，只保留一个同名定义。
2. 用本目录 `fmc_interface.xdc` 替换原FMC专用约束，避免同时启用两份；引脚不变，DQ输出路径预算从20 ns收紧至10 ns。
3. 顶层保持 `FMC_CONTROL=1`。`fmc_record_regs.v`、DDR模块、8 KiB RAM及采集时钟不用修改。这里复制的寄存器模块和 `sim/` 文件仅用于验证，不要重复添加为工程源。
4. 重新综合、实现并生成配套bit/ltx；检查100 MHz内部时序以及DQ输出10 ns最大路径要求。仿真通过不代表板级时序闭合。

## 修改内容

- SDCLK采样边沿间隔的保护阈值从19改为8，支持名义10 MHz并留一个UI采样周期的量化余量；这不是精确频率测量器。
- 增加第一次有效下降沿的记录，避免复位在SDCLK高相位释放时将半个周期判为超频。
- DQ输出最大路径预算收紧至10 ns。
- 原CAS3读返回流水线经真实XPM RAM验证后保留；协议和模块端口不变。

## 发给 STM32 同事的要求

- 修改系统时钟，使实际 HCLK=30 MHz；FMC SDCLK=HCLK/3=10 MHz。
- 不能仅在168 MHz下修改AHB分频得到30 MHz；需要按实际晶振重新配置时钟树。检查RCC_GetClocksFreq和实测PG8时钟。
- 更新SystemCoreClock、delay、SysTick/LocalTime、以太网MDIO等依赖时钟的设置，再启用网络分支；不使用之前168/16的低速测试分支。
- `FPGA_FMC_SDCLK_MAX_HZ` 更新到10000000，保留实际频率检查；不允许168/3=56 MHz。
- Bank2、16位、13行/8列、4内部bank、CL3、RPIPE2、ReadBurst关闭、模式寄存器0x0230保持。
- SDRAM初始化时序周期数保持2/7/4/7/3/2/2，CTB2为bit3。
- 基地址、寄存器地址、SET/GET、READ_NEXT/ACK/RELEASE和8192字节数据窗口保持。
- 首次网络联调用SET 1,1再GET：原始400000字节，49块，末块6784字节；当前HEX发送会产生800000个数据字符，结束标记另计。

## 验证范围

证据保存在 `reports/`。模块仿真与独立综合不能代替当前完整工程的实现、外部输入建立时间和上板验证。

本版外部要求：SDCLK名义1～10 MHz，周期至少100 ns，高/低相位各至少45 ns；命令/地址/掩码/写数据在上升沿前稳定至少30 ns。FPGA UI必须保持100 MHz。

严格技能格式门禁结果单独披露；先前已有的端口分组和格式问题没有作为此次频率修复的一部分重写。不可将Vivado功能验证称为该格式门禁通过。
